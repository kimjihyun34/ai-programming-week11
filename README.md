# 성적 CSV 읽기 및 자동 테스트 실습

## ① 무엇을 하나요 (What)

성적 CSV 파일을 읽어 유효한 성적 목록과 잘못된 행의 기록을 반환하는 프로그램입니다.

- 이름이 있고 점수가 0~100 사이의 정수이면 정상 결과에 포함합니다.
- 열 개수 오류, 이름 누락, 점수 누락, 정수가 아닌 점수, 범위 초과가 있으면 해당 행을 건너뛰고 이유를 기록합니다.
- 빈 줄은 기록 없이 건너뜁니다.
- 같은 이름도 동명이인일 수 있으므로 모두 유지합니다.
- 첫 번째 CSV 레코드는 헤더로 간주하여 제외합니다. 헤더 내용 자체는 검사하지 않습니다.

`load_scores(path)`는 다음 두 목록을 반환합니다.

- `kept`: `(이름, 점수)`의 목록
- `skipped`: `(줄 번호, 원본 필드를 쉼표로 연결한 문자열, 제외 이유)`의 목록

## ② 왜 만들었나요 (Why)

성적 CSV에 잘못된 값이 섞여 있어도 정상 데이터는 계속 읽고 오류가 있는 행만 구분하는지 확인하고 싶었다. 실행 결과를 눈으로만 확인하지 않고 pytest로 자동 검증하는 방법을 익히고 내가 작성한 테스트와 AI가 만든 테스트의 차이를 비교하기 위해 만들었다.

## ③ 어떻게 쓰나요 (How)

### 실행 환경

- Windows PowerShell
- Python 3.14.8에서 테스트했습니다.
- 프로그램은 Python 표준 라이브러리를 사용합니다.
- 자동 테스트에는 pytest와 pytest-cov를 사용합니다.

### 저장소 내려받기

```powershell
git clone https://github.com/kimjihyun34/ai-programming-week11.git
cd ai-programming-week11
```

이미 내려받았다면 저장소 폴더에서 터미널을 열고 다음 단계부터 진행합니다.

### 테스트 도구 설치

```powershell
py -m pip install pytest pytest-cov
```

### 프로그램 실행

저장소 폴더에서 아래 명령을 실행합니다.

```powershell
py load_scores.py scores.csv
```

유효한 학생 목록과 건너뛴 행의 수 및 제외 이유를 출력합니다.

다른 파일을 읽으려면 `scores.csv`를 해당 파일 경로로 바꿉니다.
파일이 없거나 읽을 수 없으면 예외가 발생합니다.

## ④ 어떻게 테스트하나요

### 기본 테스트 실행

```powershell
py -m pytest test_load_scores.py -v
```

### 커버리지 측정

```powershell
py -m pytest test_load_scores.py -v --cov=load_scores --cov-report=term-missing
```

### 실제 확인한 결과

```text
Name             Stmts   Miss  Cover   Missing
----------------------------------------------
load_scores.py      45      0   100%
----------------------------------------------
TOTAL               45      0   100%

13 passed in 0.31s
```

테스트 함수 8개가 매개변수 반복을 포함해 총 13개 케이스로 실행되었고, 모두 통과했습니다.

검증한 항목은 다음과 같습니다.

- 정상 파일 읽기
- 없는 파일에서 FileNotFoundError 발생
- 헤더만 있는 파일
- 점수 경계값 -1, 0, 1, 99, 100, 101
- 빈 줄 무시
- 이름 안의 쉼표 처리
- 이름이 빈 행의 제외 기록
- 프로그램 직접 실행 시 출력 내용

초기 커버리지는 76%였습니다.
이름이 빈 행과 프로그램 직접 실행 시 출력을 검증하는 테스트를 추가한 뒤 100%가 되었습니다.

커버리지 100%는 실행 대상 구문을 모두 실행했다는 뜻이며,
모든 입력에서 버그가 없다는 보장은 아닙니다.

### AI 테스트 비교

AI가 생성한 A·B 테스트는 수정하지 않은 원본으로 보관했습니다.

| 항목 | 내 테스트 | A: 코드 제공 | B: 명세 제공 |
| --- | --- | --- | --- |
| 테스트 함수 수 | 8개 | 24개 | 20개 |
| 수정 없이 실행·통과 | O | X | X |
| pytest.raises 사용 지점 | 1개 | 3개 | 4개 |
| 0·100·101 검사 | 모두 포함 | 모두 포함 | 0·100 포함, 101 없음 |
| 커버리지 | 100% | 측정 불가 | 측정 불가 |

- A는 없는 `scores` 모듈을 불러와 수집 단계에서 중단되었습니다.
- B는 없는 `grades` 모듈을 불러와 수집 단계에서 중단되었습니다.
- A·B는 실제 대상 함수 검증이 실행되지 않았으므로 커버리지를 측정 불가로 기록했습니다.
- 기본 검증 시에는 반드시 `test_load_scores.py`를 지정합니다.
- 파일 지정 없이 전체 pytest를 실행하면 A·B의 import 오류로 중단될 수 있습니다.

### 함정 실험

AI가 작성한 테스트에서 `[70, 85, 60, 95]`의 최댓값 기대값은 95였습니다.
따라서 해당 답변에서는 잘못된 결과 85를 정답으로 굳히지 않았습니다.

이 결과는 생성된 테스트의 기대값을 읽고 확인한 것이며,
함정 테스트를 실제로 실행해 버그 검출까지 확인한 것은 아닙니다.

## ⑤ 파일 구성

| 파일 | 하는 일 |
| --- | --- |
| `load_scores.py` | CSV 읽기, 성적 검증, 결과 반환 및 직접 실행 시 출력 |
| `scores.csv` | 정상 행과 잘못된 행이 섞인 실습 데이터 |
| `empty.csv` | 헤더만 있는 실습 데이터 |
| `weird.csv` | 비정상 입력 실습용 데이터 |
| `test_load_scores.py` | 기본 검증용 테스트 |
| `helpers.py` | 경계값 테스트용 CSV 생성 도우미 |
| `test_ai_A.py` | 코드를 제공해 AI가 만든 테스트 원본 |
| `test_ai_B.py` | 명세를 제공해 AI가 만든 테스트 원본 |
| `bug3_logic.py` | 함정 실험용 버그 프로그램 |
| `bug3_ai_result.py` | 함정 실험에서 받은 AI 테스트 코드 |
| `prompts.txt` | A·B 실험 프롬프트 |
| `README.md` | 프로그램 설명과 실행 안내 |
| `.gitignore` | Git에서 제외할 파일 설정 |
| `LICENSE` | 라이선스 조건 |

경계값 테스트 실행 중 생성되는 `임시.csv`는 테스트용 파일이며 저장소에 포함할 필요가 없습니다.
